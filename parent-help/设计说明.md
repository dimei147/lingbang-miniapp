# 2026-11-13 · 七场景与自然月助力限制（历史版本 v3）

入口：[双视角七场景演示](家长端-助力活动-场景演示.html)。主产品原型仍为 [助力免费发布](家长端-助力免费发布.html)。新增独立场景演示页，选择器置于手机外；原产品页面不加入身份切换、模拟结果或预览卡片按钮。此次应用户明确要求，助力者场景以微信收到分享卡片为起点，卡片是该场景的实际入口。

## 七个场景

| 视角 | 场景 | 初始状态与可操作路径 |
| --- | --- | --- |
| 发起者 | 01 发起助力 | 确认发布页 → 浅红助力入口 → 发起确认半弹窗 → 创建 24 小时活动 → 邀请海报 |
| 发起者 | 02 助力中 | 已有 2 位好友助力，还差 1 人；继续邀请、查看记录与规则 |
| 发起者 | 03 助力成功 | 已集齐 3 人，减免 ¥9.9 → 免费发布 → 确认 ¥0 → 发布成功 |
| 发起者 | 04 助力失败 | 24 小时到期，仅有 2 人；明确未取得免费资格，可重新发起或付费发布 |
| 助力者 | 05 助力成功 | 微信分享卡片 → 手机号快捷登录 → 允许授权 → 助力页面 → 点击助力 → 1/3 增至 2/3，成功消耗本月次数 |

| 助力者 | 07 本月次数用尽 | 相同登录路径 → 助力失败、本月可助力 0 次；原进度保持 1/3 |

三条助力者场景每次切换均重置为未登录，必须先走手机号授权；拒绝或关闭授权弹窗停留在登录页，不能进入助力页面。每次切换场景都会恢复对应预设，不影响主原型的本地活动记录。

## 月度次数口径

- 每位用户每个自然月仅能成功助力 **1 次**，全部需求共享；不等于每个需求各有 1 次。
- 自然月按北京时间（Asia/Shanghai），从每月 1 日 00:00 起计算，下月 1 日 00:00 自动获得新月份的机会。
- 仅成功助力扣次数。打开卡片、登录、拒绝授权、仅分享、失败和重复访问不扣次数。
- 同一需求重复打开，优先显示「此次需求已助力过」；本月给其他需求助力过，显示「助力失败 / 本月助力次数已用尽」。
- 发起人不能助力自己；活动结束或过期不能继续助力；活动过期、重开不退回好友已使用的月度次数，重开的人数不继承。
- 活动页 8 条说明、发起弹窗、分享卡片、海报及助力者页面同步展示月度限制。

# 家长端 · 助力免费发布（研究稿 v1）

2026-11-12。入口：[交互原型](家长端-助力免费发布.html)。默认展示确认发布页；左侧「完整家长路径」从首页重新体验并重置演示数据。没有修改现有「家长端-付费与会员.html」。

## 本版建议

在用户填写完需求后提供助力选项：需求已经具备明确的发布意图，活动优惠也可以直接绑定本次发布。首页无需先做独立活动页和另一套填单流程。

用户已提出的确定条件只有「邀请 3 个微信好友助力，免费发布此次需求」。下面的有效期、身份限制、变更规则与达标确认均是本版待讨论方案。

## 两条核心路径

**家长：**首页发布需求 → 填写表单 → 确认发布页 → 选择「3 位好友助力，免费发布」→ 查看时间与规则，确认发起 → 生成助力中的需求草稿 → 邀请微信好友 → 查看 0/3、1/3、2/3 → 达标 3/3 → 核对减免金额并确认 → 发布成功 → 我的需求。

**好友：**微信收到小程序卡片 → 打开好友助力页 → 点击「帮好友助力」→ 必要时完成微信身份识别 → 助力成功。已经帮过则直接显示已助力；本人与已结束、已到期邀请均不能助力。好友无需支付、不需要选择老师或家长身份、不需要填写找老师表单。

微信界面是分享效果示意，原型不发送真实消息。左侧切换好友 A/B/C 后可逐个点击助力，切换为发起人本人可查看拦截状态。

## 页面安排

| 页面 | 核心内容与动作 |
| --- | --- |
| 确认发布 | 新增助力免费入口，保留 ¥9.9 单次发布与会员月卡/年卡；会员已有权益直接免费发布 |
| 发起确认 | 告知 3 人门槛、24 小时时限、当前不会公开需求、可改付费 |
| 助力进度 | 缺少人数、3 个助力位、真实流逝的倒计时、关联需求、好友记录、邀请主按钮 |

## 规则与边界（本版假设）

- **只免本次普通需求发布费**，不含后续课时费和定向邀约费；不发通用券、不叠加多个活动。
- **24 小时内集齐 3 人**。截止前达到 3 人即进入待发布，停止倒计时；本版不另设达标权益失效期。若担心长期占用，可单独讨论达标后有效期。
- **新老微信用户均可**。同一好友对同一次助力活动只计 1 次，发起人不能助力自己；仅分享或打开不计数。原型模拟登录不等于真实微信授权实现。
- **达标后由家长确认发布**。避免家长临时改变安排却因第三人助力自动上线；代价是可能有用户达标后忘记发布。
- **修改需求需结束当前助力**，重新发起重置人数。这个规则易解释与实现，但对用户较严；下一轮可比较「仅改年级/科目等核心信息才重置」的方案。
- **到期保留需求内容**，允许重新发起；本版重开重新计时、人数清零。不限制原型中的重开次数，正式参与频次需单独确定。
- **中途可以付费或开通会员并发布**。取消、失败时保留助力；成功后结束助力，旧邀请无法继续累加，已支付不追溯返款。
- **离开不取消活动**，可从我的需求继续。原型以浏览器本地数据保存活动进度；不跨设备同步。

## 可继续研究的三个点

1. 24 小时是否足够，还是应当允许更长时间？本版仅用于体验紧迫感，不代表活动政策已定。
2. 修改后全部清零是否过严，能否允许改时间、补充要求等轻微变更？
3. 是否需要达标提醒？建议在家长同意接收提醒后提供消息；原型未实现消息订阅和真实通知。

正式验证时可观察：确认页发起助力比例、收到卡片后的有效助力比例、3 人达标耗时、达标后最终发布比例，以及放弃助力转付费的比例。
